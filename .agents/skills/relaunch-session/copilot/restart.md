# Relaunch Session — Copilot CLI

Run with `<sdk>` = `copilot`.

- The agent is the nearest `copilot.exe` ancestor of the tool shell, not `$env:COPILOT_LOADER_PID`: a copilot started from another copilot's shell inherits that variable from the outer one. The session is `$env:COPILOT_AGENT_SESSION_ID`.
- Exit: each Ctrl+C takes one step — cancel the running turn, clear the input box, arm the exit confirmation, quit — so the worker keeps pressing, up to five times, until copilot exits. Any draft the user has typed in the input box is cleared.
- Relaunch line: `copilot.exe <kept launch args> <extra args> --resume <session id>`, with `-Prompt` text passed as `-i <prompt>` (copilot's positionals are subcommands). It names `copilot.exe` so a shell function or alias called `copilot` cannot add its arguments a second time.
- Dropped launch args: `--resume`/`-r`, `--continue`, `--session-id`, `--connect`, `--name`/`-n`, `--interactive`/`-i`, `--prompt`/`-p`, `--fleet`, `--attachment`, and the hidden `--worktree`/`-w`, `--cloud`, `--new-session-id` (clap refuses each with `--resume`), in any spelling, including attached short values such as `-r<id>`. Option arity is read from the installed `copilot --help`. An interactive copilot has no subcommand and clap rejects values starting with `-`, so a word after a hidden option such as `--prefer-version` is that option's value and stays with it.
- `-ExtraArgs`: copilot keeps the last value of a repeated single-value option (`--model`, `--mode`) and accumulates repeatable ones (`--add-dir`, `--allow-tool`, `--deny-tool`), so an original `--deny-tool` stays in force. Besides the dropped options above, these are rejected: `--acp`, `--help`/`-h`, `--version`/`-v`, and the hidden `--server`, `--headless`, `--managed-server`, `--stdio`, `--embedded-host`, `--print-debug-info`, `--collect-debug-logs`. Before the exit, the script dry-runs `copilot.exe <relaunch args> --version`; clap checks conflicts and values first, so a combination copilot refuses (`--mode` over an original `--autopilot`, `--plan` with `--autopilot`, an invalid `--context`) fails the call and the session keeps running.
- Folder trust: the relaunch's working directory is the last `-C`, else the session's stored cwd. If it is not trusted (not listed, nor an ancestor or its git root, in `trustedFolders` of `config.json` under `--config-dir`, `COPILOT_HOME`, or `~/.copilot`), the worker adds it to `trustedFolders` after copilot exits, so the relaunch starts without the trust question. The entry is persistent, the same as answering "Yes, and remember this folder". An extra `-C` must be an absolute path to an existing directory; a failed write is logged as `TrustFailed`, and copilot then asks as usual.
- One copilot process can host several live sessions (Sessions sidebar, `--ui-server`). Exiting ends all of them, and only this session is relaunched. When other live sessions share the process, tell the user before restarting.
- The user can restart without this skill: `/restart` in the CLI restores supported live sessions in-process. This skill is for when the agent itself must restart or exit.
